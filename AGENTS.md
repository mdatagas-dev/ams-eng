# ams-eng

Engineering asset management: Next.js 16 (App Router) frontend + Express 5 API in `server/`. Prisma 7 against PostgreSQL. Two separate processes, not one.

## Commands

```bash
npm run dev          # Next dev server (Turbopack)
npm run dev:api      # Express API (tsx watch, port 4000)
npm run build        # next build
npm run build:api   # tsc -p server/tsconfig.json  -> dist/server
npm run start        # next start
npm run start:api    # node dist/server/index.js

npm run lint         # eslint (flat config)
npm run typecheck    # BOTH tsconfigs: root (Next, excludes server/) + server/tsconfig.json
npm run format       # prettier --write "**/*.{ts,tsx}"
npm test             # node --import tsx --test server/*.test.ts

npm run db:generate  # prisma generate (also runs on postinstall)
npm run db:migrate   # prisma migrate dev
npm run db:deploy    # prisma migrate deploy
npm run db:seed      # prisma db seed (tsx prisma/seed.ts)
npm run db:studio    # prisma studio
```

Run order before commit: `lint -> typecheck -> test`. `typecheck` must pass both projects; a clean root `tsc --noEmit` does NOT cover the server.

Single test file: `node --import tsx --test server/input.test.ts` (node:test runner, no Jest/Vitest).

## Architecture

**Two tsconfigs.** Root `tsconfig.json` (bundler, `noEmit`, `@/*` -> `./*`) covers the Next app and **excludes `server/`**. `server/tsconfig.json` extends it but switches to `NodeNext` + `lib: ES2022`, emits to `../dist/server`. Server files import with `.js` extensions (NodeNext ESM) — keep this, don't drop them.

**Two processes.** Next frontend talks to Express over HTTP via `lib/api.ts` (`apiGet`/`apiSend`, server-only). `API_URL` env (default `http://localhost:4000/api`). Auth is a Bearer session token stored in the `ams_session` httpOnly cookie; Next server actions forward it. Public (unauthenticated) routes live under `/api/public` (cabinet checkout kiosk).

**Route groups.** `app/(workspace)/` holds authenticated pages behind a layout that calls `getCurrentUser()` and redirects to `/login` on 401. `app/login` and `app/checkout/cabinet/[id]` are outside the group (public). `app/data/` is empty (gitkeep only).

**Next 16 specifics.** `params` is a `Promise` — await it in page components (`const { id } = await params`). Use `connection()` from `next/server` to opt pages into dynamic rendering. See `node_modules/next/dist/docs/` for anything non-trivial; App Router only, no Pages Router, no `getServerSideProps`.

## Prisma

- Generator `prisma-client` (not the legacy `prisma-client-js`) outputs to `server/generated/prisma/` — gitignored, regenerated by `postinstall` and `db:generate`. Import the client from `./generated/prisma/client.js`.
- Driver adapter `@prisma/adapter-pg` (`PrismaPg`) — no `prisma-client` binary engine. `DATABASE_URL` required (Postgres).
- `prisma.config.ts` sets schema/migrations/seed paths and reads `DATABASE_URL` via `env()`.
- Migrations are timestamped (e.g. `20260726000000_add_cabinet_checkout`). Run `db:migrate` in dev, `db:deploy` in prod/CI.
- Seed (`prisma/seed.ts`) bootstraps two users from `BOOTSTRAP_SUPERUSER_*` / `BOOTSTRAP_ADMIN_*` env vars — only creates them if all three fields are set. Seed is idempotent for departments/cabinets (upsert); assets only seed when table is empty.

## Conventions

- **Prettier**: no semicolons, double quotes, es5 trailing comma, LF endings, `printWidth: 80`, Tailwind plugin with `tailwindFunctions: ["cn", "cva"]` and `tailwindStylesheet: app/globals.css`.
- **shadcn**: `components.json` uses `style: base-luma`, `iconLibrary: remixicon`, aliases `@/components/ui`, `@/lib/utils`, `@/hooks`. CSS vars enabled, `stone` base color. Add components via `npx shadcn@latest add <name>`.
- **Input validation**: `server/input.ts` helpers (`text`, `nullableText`, `oneOf`, `uuid`, `date`, `timestamp`, `integer`, `username`, `secret`) throw `ApiError(status, message)`. Trust-boundary validation lives here, not in routes. Follow this pattern for new endpoints.
- **Errors**: `ApiError` surfaces as JSON `{error}`. Prisma `P2002/P23505` -> 409, `P2003/P23503` -> 400, `P2034` -> 409. Don't swallow these in route code; let the global handler in `server/app.ts` map them.
- **Concurrency**: mutation transactions use `Serializable` isolation and optimistic locking via `updatedAt` timestamp comparison (see `PATCH /assets/:id`). Preserve this on new mutating endpoints.
- **`ponytail:` comments** mark deliberate shortcuts with their ceiling + upgrade path — keep them, don't strip.

## Env

Copy `.env.example` to `.env`. Required: `DATABASE_URL`. API defaults: `API_PORT=4000`, `API_HOST=127.0.0.1`. `API_URL` must be reachable from the Next process. Set `BOOTSTRAP_*` before first `db:seed` to create initial super-user + admin.

## Testing

Only `server/*.test.ts` currently (`input.test.ts`, `password.test.ts`). node:test + `node:assert/strict`. No fixtures, no DB, no network. Add tests alongside server modules following the same pattern.
